# r3bl-build-infra v0.0.6 Release Notes

**r3bl-build-infra** provides developer tools and utilities for Rust projects and
documentation automation:

- 📐 **`cargo-rustdoc-fmt`**: Lossless CST-based CLI tool (and `cargo` subcommand) that
  formats Markdown tables, converts inline links into sorted reference-style links,
  auto-links known technical terms, and normalizes code fence language tags in rustdoc
  comments (`///` and `//!`)—supporting whole-workspace, git-diff, and surgical
  line-range formatting.

Install with:

```bash
cargo install r3bl-build-infra --force
```

---

## Why `cargo-rustdoc-fmt` Was Rewritten from the Ground Up in v0.0.6

In `v0.0.1`–`v0.0.5`, `cargo-rustdoc-fmt` joined contiguous rustdoc comment blocks into
monolithic strings, shielded code blocks and inline spans with ad-hoc Unicode sentinel
placeholders (`ContentProtector` / `◄◄◄PROTECTED_CONTENT►`), and ran global regular
expressions and `pulldown-cmark` passes over the text. That design suffered from
fundamental limitations:

1. **Fragile Regex & Sentinel Placeholder Interactions**: Complex Rust type signatures
   (such as `` `Mutex<Option<Arc<ThreadState<W, E>>>>` ``), ASCII architecture diagrams,
   multi-line wrapped reference definitions, and escape sequences (`[200~`) repeatedly
   collided with regex character classes or HTML tag heuristics.
2. **No Source Line Span Tracking**: Because doc blocks were flattened into strings
   without line coordinate metadata, surgical line-range formatting (`--lines`) was
   impossible without an isolated bypass pipeline.
3. **Heavy Dependency Footprint**: Pulling in `pulldown-cmark`, `regex`, `once_cell`, and
   `serde_json` added compile-time weight and slowed down test execution.

### The v0.0.6 Solution: Lossless Two-Level Concrete Syntax Tree (CST) & Zero-Regex Scanners

`v0.0.6` replaces the entire legacy pipeline (`extractor.rs`, `RustdocBlock`,
`content_protector.rs`, `table_formatter.rs`, `link_converter.rs`, and
`technical_term_linker.rs`) with a **lossless two-level Concrete Syntax Tree (`cst/`)**
and **direct byte/slice scanners** (`formatters/`) with **zero regex dependencies**:

```text
.rs source file
  └── Level 1: SourceFileCst (preserves LineEndings [LF/CRLF] & TrailingNewline)
        ├── FileChunk::Code          ──► preserved 100% byte-for-byte
        └── FileChunk::DocBlock      ──► Level 2: DocBlockCst
              ├── DocNode::Paragraph             (inline link conversion & technical term linking)
              ├── DocNode::Table                 (GFM column width calculation, alignment & padding)
              ├── DocNode::CodeFence             (fence language tag normalization; body untouched)
              ├── DocNode::HtmlComment           (protected verbatim: e.g., <!-- TOC --> blocks)
              ├── DocNode::ReferenceDefinitions  (collected, deduplicated & sorted at block bottom)
              └── DocNode::BlankLine
```

- **100% Byte-for-Byte Preservation Guarantee**: Unmodified `FileChunk::Code` chunks and
  any `DocNode` with `FormatStatus::Unchanged` emit their original `raw_lines` verbatim
  during `SourceFileCst::reconstruct()`, preserving exact indentation prefixes,
  `LineEndings` (`Unix` LF vs `Windows` CRLF), and `TrailingNewline` (`Present` vs
  `Absent`).
- **Structural Isolation Without Placeholders**: Because `DocNode::CodeFence` and
  `DocNode::HtmlComment` are distinct CST node variants—and inline backtick spans are
  skipped by direct byte-slice scanners (`cst/link_reference.rs` and
  `formatters/technical_term/markdown_spans.rs`)—ASCII diagrams, code examples, and
  generic Rust types are structurally immune to corruption without sentinel placeholders.
- **Type-Safe Coordinate Spans (`r3bl_tui` Integration)**:
    - Every `FileChunk` and `DocNode` tracks its exact 0-based `RangeInclusive<CRow>`
      source span in Canvas coordinates, while `TableData` tracks column indices and
      widths using `CCol` and `CWidth` with `ArrayBoundsCheck::overflows`.
    - 1-indexed CLI line numbers are parsed at the boundary into `EditorLineNum` ("Parse,
      don't validate") and converted to 0-based `RangeInclusive<CRow>`, using the
      `RangeOverlapResult` (`Overlaps` / `Disjoint`) witness enum from `r3bl_tui` to
      filter CST nodes.
    - Eliminated boolean blindness across `FormatOptions` and `ProcessingResult` using
      explicit domain enums: `PassPolicy` (`Enabled` / `Skipped`), `ExecutionMode`
      (`ApplyChanges` / `CheckOnly`), `Verbosity` (`Quiet` / `Verbose`), and
      `FormatStatus` (`Modified` / `Unchanged`).

## New Features in v0.0.6

### 1. Surgical Line-Range Formatting (`--lines-force` / `--lines`)

Format only the rustdoc nodes overlapping a specific 1-based inclusive line range in a
single `.rs` file while leaving all other lines in the file 100% untouched:

```bash
# Supports colon (10:20), Rust ranges (10..20, 10..=20), hyphen (10-20), or single line (42)
cargo rustdoc-fmt --lines-force 400:445 tui/src/lib.rs
cargo rustdoc-fmt --lines 120..=160 tui/src/core/pty/mod.rs
```

- **Doc-Block-Wide Reference Aggregation**: When inline links inside the targeted line
  range are converted to `[text]` reference links, their `[text]: target` definitions are
  automatically merged, deduplicated, and sorted into the enclosing doc block's bottom
  `DocNode::ReferenceDefinitions` section.
- **Automatic `// rustdoc-fmt: skip` Bypass**: Explicitly targeting a line range with
  `--lines-force` / `--lines` overrides file-level `// rustdoc-fmt: skip` directives so
  large files (like `lib.rs`) can be formatted surgically section-by-section.
- **Decoupled from `#![rustfmt::skip]`**: `cargo-rustdoc-fmt` no longer conflates
  `#![rustfmt::skip]` with `// rustdoc-fmt: skip`—files that skip `rustfmt` to preserve
  manual Rust code alignment now have their rustdoc comments formatted normally, while the
  trailing `cargo fmt` pass natively respects `#![rustfmt::skip]`.
- **Strict Target Validation**: Validates at startup that `--lines-force` targets exactly
  one existing `.rs` file (rejecting directories, non-Rust files, or `--workspace`).

### 2. Code Fence Language Tag Normalizer (`--fences-only`)

Rustdoc treats unlabeled fenced code blocks as Rust by default, making ` ```rust `
redundant. A new CST pass (`formatters/code_fence.rs`) normalizes opening fence tags
across all `DocNode::CodeFence` nodes while keeping the code block body untouched:

- ` ```rust ` → ` ``` ` (standalone redundant `rust` tag removed)
- ` ```rust,<attr> ` → ` ```<attr> ` (e.g., ` ```rust,no_run ` → ` ```no_run `,
  ` ```rust,ignore ` → ` ```ignore `, ` ```rust,compile_fail ` → ` ```compile_fail `)
- Non-Rust fences (` ```text `, ` ```bash `, ` ```markdown `, bare ` ``` `) and words starting
  with `rust` (e.g., ` ```rustic `) are never modified.
- Applied across all **884 active `.rs` files** in the workspace (cleaning up 206 code
  fences across 66 files).

### 3. Expanded Technical Term Auto-Linker (`--terms-only` & `--terms-file`)

Rebuilt the technical term auto-linker (`formatters/technical_term/`) on top of the CST
with 5 focused submodules (`link_terms_entry_point.rs`, `upgrade_term.rs`,
`markdown_spans.rs`, `ref_defs.rs`, `technical_term_dictionary.rs`) and simplified
`known_technical_term_link_dictionary.jsonc` into a clean flat term-to-target registry
with **49 canonical terms**:

- **19 New Seed Terms Added**:
    - **Stdlib I/O (`std::io`)**: `stdout`, `stderr`, `stdin`, `stdio`
    - **Crate Dependencies**: `tokio`, `crossterm`, `mio`, `portable_pty`
    - **Internal Module & Spec Links**: `pty` (`crate::core::pty`) and `PTY` (Wikipedia
      Pseudoterminal)
    - **OS Signals, Terminal Protocols & Unicode**: `EOF`, `SIGWINCH`, `SIGINT`,
      `SIGTERM`, `grapheme`, `Unicode`, `RGB`, `epoll`, `kqueue`, `Bracketed paste`,
      `truecolor`, `termios`
- **Context-Aware Upgrading & Reconciliation**:
    - Upgrades bare or backticked terms (e.g., `` `ANSI` `` → `[`ANSI`]`) and
      injects/updates canonical reference definitions at the bottom of the doc block.
    - **Qualified Path Guards**: Protects qualified Rust paths (such as
      `std::io::stdout()`, `crossterm::event::read()`, `mio::Poll::new()`) and inline code
      expressions from being split or falsely linked.
    - **Multi-Line Reference Definition Preservation**: Properly parses and preserves
      2-line wrapped reference definitions (`[label]:\n    https://...`) created by
      `rustfmt` without orphaning URL lines.
    - Supports custom dictionary overrides via `--terms-file <PATH>`.

### 4. New CLI Flags & Workspace Discovery Improvements

- `--lines-force <RANGE>` (alias `--lines <RANGE>`): Surgical 1-based line-range
  formatting (`10:20`, `10..20`, `10..=20`, `10-20`, `42`).
- `--fences-only`, `--terms-only`, `--tables-only`, `--links-only`: Run individual CST
  formatting passes in isolation.
- `--skip-folder-matches <PATTERN>`: Comma-separated path component filter (defaults to
  `test_data` so test fixtures are skipped automatically; pass `""` to disable).
- `--dry-run` (`-d`): Preview which files would be processed without reading or modifying
  them.
- `--skip-cargo-fmt`: Skip running `cargo fmt` on modified files after rustdoc formatting.
- **Standalone Crate Support**: `workspace_utils::get_workspace_root` now falls back to
  single-crate `[package]` roots when run outside a multi-crate `[workspace]`.

## Dependency Removal & ~50x Faster Test Suite

- **Dropped 5 Heavy Dependencies**: Removed `pulldown-cmark`, `regex`, `once_cell`,
  `serde_json`, and `pretty_assertions` from `build-infra/Cargo.toml`.
- **Consolidated Golden-File Test Suite**: Unified all 23 end-to-end `.rs` golden-file
  fixtures and idempotency checks under `validation_tests/test_data/complete_file/`,
  slashing `r3bl-build-infra` test suite runtime by **~50x** (from **~3.6s down to
  ~0.07s**).
- **Workspace Dependency Update**: Updated `r3bl_tui` dependency to **`0.8.0`**.
